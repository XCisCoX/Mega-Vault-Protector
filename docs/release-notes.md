# Release notes

Every release and beta publishes a change summary generated by
`scripts/release-notes.py` inside the release job. The comparison base is the
newest `vX.Y.Z` tag that the released commit already contains (stable tags by
default, previous betas with `--include-betas`), so a beta describes everything
a user gets on top of the last stable build, not just the commits since the
previous beta.

## What the generator does

1. Reads the commit range with `git log`, keeping the subject and body.
2. Groups commits by conventional-commit type (`feat`, `fix`, `docs`, …) and
   shows the scope, e.g. `android: speak protocol 4`.
3. Summarises `git diff --numstat`: authored files, lines, and which area they
   touch (desktop, Android, sync server, extensions, core, CI, docs).
4. Lists vendored `third_party/` updates separately, so a QuickJS bump does not
   hide the user-facing changes.
5. Builds a bounded authored diff (120 KB, vendored and low-signal paths
   excluded) for explanations.

The result is deterministic and needs no network. If an AI pass is configured,
the same facts plus that bounded diff are sent to an OpenAI-compatible endpoint
and its prose is published above the factual summary. A timeout, an HTTP error
or an empty answer silently falls back to the factual summary: a release never
fails because a model is unavailable, and the model never decides which commits
exist.

## Enabling the AI wording

Set a repository secret and optionally a model:

```sh
gh secret set MVP_NOTES_API_KEY --repo XCisCoX/Mega-Vault-Protector
gh variable set MVP_NOTES_MODEL --repo XCisCoX/Mega-Vault-Protector --body gpt-4o-mini
gh variable set MVP_NOTES_ENDPOINT --repo XCisCoX/Mega-Vault-Protector \
  --body https://api.openai.com/v1/chat/completions
```

`MVP_NOTES_ENDPOINT` lets you use any OpenAI-compatible provider; the key is
sent only as a bearer token to that endpoint and is never printed. Without the
secret the workflow still produces notes, just without the prose.

## Local use

```sh
# Preview what the next beta would say, without calling any model
python scripts/release-notes.py --auto --to HEAD --version v2.0.22-beta.1 --no-ai

# Compare two explicit refs, write to a file
python scripts/release-notes.py --from v2.0.20 --to HEAD --out notes.md

# Compare against the previous beta instead of the last stable release
python scripts/release-notes.py --auto --include-betas --to HEAD --no-ai
```

Tests: `python -m unittest discover -s tests/scripts -v` builds a throwaway git
repository and checks grouping, vendored separation, and beta comparison.
