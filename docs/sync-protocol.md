# Self-hosted sync v2 — implementation contract

Issue #3 replaces remote decrypted browsing with an opaque encrypted-package relay. The server MUST NOT receive vault passwords or the shared package secret. Local vaults remain independently password protected. Clients use the existing MVPK export/import format and a shared random 32-byte recovery secret encoded as 64 lowercase hex characters as the package password. Names, folder paths and content are inside MVPK, not in server JSON. Recovery secret is shared out-of-band, never through a server pairing code. Device tokens are separate from the recovery secret.

## API

JSON responses, except blob downloads. IDs are 32 lowercase hex; blob digests are SHA-256 (64 lowercase hex). Integers are JSON integers. Auth: `Authorization: Bearer <64 lowercase hex device token>`. Pairing tokens are single-use, expire in ten minutes, and are generated by the local server administration CLI.

* `GET /healthz`: unauthenticated, `{ "ok": true, "protocol": 2 }`.
* `POST /v2/pair`: `{ "code": "...", "name": "..." }` -> `{ "device_id": "32hex", "token": "64hex" }`. Rate limit failed attempts. Server stores only token/code hashes. Name is a non-sensitive device label, not a file name.
* `GET /v2/objects`: `{ "objects": [{ "id": "32hex", "revision": 1, "blob": "64hex", "size": 123, "deleted": false, "sequence": 1 }] }`. Complete latest manifest; empty list initially. Order by sequence. No plaintext names. MVP caps catalog at 10000 objects; reject additional new objects rather than silently truncate.
* `GET /v2/objects/{id}/history`: `{ "versions": [same records] }`. Immutable history.
* `HEAD /v2/blobs/{hash}`: `Content-Length` is complete blob size, `X-Upload-Offset` is durably stored byte count, `X-Blob-Complete: true|false`. 404 if no upload exists.
* `PUT /v2/blobs/{hash}?offset=N`: `X-Blob-Size: total`, octet-stream body (1 MiB max). Append only at current durable offset; a mismatch returns 409 `{ "offset": actual }`. Result `{ "offset": N, "complete": false }`. When total is reached validate SHA-256, atomically finalize blob and return complete true. Existing complete matching blob returns total offset and complete true (idempotent). Invalid hash 422 and remove partial. Enforce quota incl partials.
* `GET /v2/blobs/{hash}`: complete blob bytes; `Range: bytes=N-M` supported. 206 + Content-Range, 416 for invalid ranges. No partial uploads served. Stream bounded chunks.
* `POST /v2/objects/{id}`: `{ "base_revision": 0, "blob": "64hex", "size": 123, "deleted": false, "operation_id": "32hex" }` -> committed latest object record. Base 0 creates. Existing object's base MUST match current revision; 409 `{ "current": record }` otherwise. Idempotency operation id is scoped to device, replay with identical payload returns original committed result, different payload rejected. Validate blob complete and size match before commit. Delete tombstone has blob empty and size zero; history retained.
* `GET /v2/devices`: `{ "devices": [{ "id": "32hex", "name": "...", "revoked": false }] }`. Paired devices can view labels, not token hashes. Revocation and pairing administration are local CLI only in MVP.

Server CLI: `python -m sync_server --data <dir> serve --host 127.0.0.1 --port 8766 [--cert cert.pem --key key.pem]`; `... pair-code`; `... devices`; `... revoke <device-id>`; `... backup <destination>`. Direct non-loopback binds require certificate and key. Container deployments use a dedicated explicit proxy mode with TLS terminating at the provided Caddy proxy, not public plaintext. SQLite + immutable filesystem blobs. Single-tenant; no automatic history GC in MVP. Backup consistent DB plus all referenced blobs; migrations use schema version and fail on newer schema. Never log request body/auth or pairing secrets in server logs.

## Native client strategy

Pair to an HTTPS URL with normal certificate validation or explicit certificate SHA-256 pin. Recovery key is entered locally and never submitted. Sync runs only against an unlocked local vault using thread-safe core APIs. Each local file has a stable random object id in private persistent client state, with last acknowledged revision and a fingerprint covering encrypted package hash, file name, complete folder path and tags. First pairing does not interpret unknown local files as server deletions.

On a changed/new local file: export a one-file encrypted MVPK with its actual relative folder path, durably stage it and a queue record before sending; upload in <=1 MiB blocks querying HEAD offsets; commit using stored base revision and stable operation id. Do not regenerate random encrypted packages or operation ids on retry. For remote changes: download resumably into private encrypted cache, verify full hash and expected size before import_package; advance seen revision only after successful local import. Do not overwrite or remove local originals on import error. Import remotely added files into ordinary local library folders. Track imported local ids to avoid echo uploads. For changed versions replace mapping only after import succeeds; retain old content if conflicting/unmapped. Automatic remote deletes in MVP are deliberately conservative: preserve local copy and show deletion notice until explicitly acknowledged; do not lose offline local edits.

If commit conflicts: keep original queue and bytes, publish edited copy under a fresh stable object id and operation id; show conflict copy status. Never blindly retry with current revision. Remote history remains available. If metadata/edit/delete conflict handling cannot be proven, preserve both local copies rather than deleting.

Offline retries: durable pending queue survives process restart, bounded exponential backoff (1–60 sec + jitter), no permanent failed-id blacklist. Explicit Retry resets timer. 401 stops retries and asks to re-pair. Never claim Synced while failed or queued work remains. Selective sync: selectable object ids or local files/folders; no background download-all without user selection. Bandwidth speed settings pace blob traffic, not control/auth.

## Boundaries

Revocation blocks future service access; cannot erase data or secrets already copied. Rotate the recovery secret and re-encrypt shared packages after compromise. Server sees device labels, object ids, sizes, timing, and revision relationships. E2EE does not prevent withholding or rollback by a malicious server; clients reject decreasing revisions locally, but no global transparency mechanism is provided. MVPK export/import currently carries directory paths and names; tag synchronization must be explicit rather than promised if unsupported by the existing format. Whole-file MVPK changes are resumable, not binary deltas; chunk deduplication is not promised. No automatic merging of text records.
