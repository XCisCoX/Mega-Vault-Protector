# Targeted Vault UI/UX Improvements Implementation Plan

**Goal:** Fix clipped authentication controls, simplify settings navigation without losing features, distinguish extensions, improve Android folders, show selection sizes, and allow intentional duplicate imports.

**Architecture:** Keep the existing Qt Widgets desktop and Kotlin/Compose Android clients over the shared C++20 core. Reuse palette tokens, existing preference keys, template storage and security flows. Separate presentation changes from import semantics so each can be reviewed and tested independently.

**Tech Stack:** Qt 5.12-compatible Widgets, C++20, CMake/CTest; Android Kotlin/Compose and JNI.

**Scope:** Planning only. Do not implement until authorized. Leave implementation uncommitted for the user; never launch the project GUI or automate their phone. Headless tests and builds are allowed during implementation.

## Proposed information architecture

Replace the crowded horizontal settings tabs with a navigable hierarchy:

- **Appearance** — theme and existing visual preferences. Default entry on first visit.
- **Library & playback**
  - Tags
  - Playback — streaming cache
  - Thumbnails — regenerate missing, explanation and progress
  - Records → Record templates (nested management page)
- **Extensions** — one distinctly separated card per extension, with its own details/settings.
- **Security** — auto-lock; password/security-profile management in a clearly labeled subsection.
- **Network** — Proxy, preserving every existing proxy option.
- **About & updates** — version, update status, manual check, automatic preferences and beta channel.

Desktop: left navigation and a right-hand content pane when space permits. Narrow windows: show a settings index, then the selected page with an in-page Back action; do not replace one overflowing tab strip with another.

Android: use a touch-friendly settings index and drill-in pages rather than a horizontally scrolling category strip. Respect status/navigation bars, keyboard insets and system Back. Use the same conceptual names, but do not invent Android features that are currently desktop-only.

All current settings remain available. Keep saved preference keys, immediate-save behavior and host signals unchanged. Preserve active navigation and scroll position while visiting a subsection within an open settings session. Never persist password input as navigation state.

## Task 6: Allow intentional duplicate imports (separate behavioral change)

**Files:**
- Modify: `core/src/vault.cpp`
- Inspect: `core/include/videovault/core/vault.hpp`, `core/src/database.cpp`, `core/src/internal/database.hpp`
- Modify relevant messaging/callers: `qt-app/src/batch_worker.cpp`, `qt-app/src/main_window.cpp`, `qt-app/src/plugin_host.cpp`
- Inspect/modify: `android/app/src/main/cpp/jni_bridge.cpp`, `android/app/src/main/java/org/megavideoprotect/app/CoreBridge.kt`, `VaultScreen.kt`, `PeerScreen.kt`, `PluginSession.kt` in the same Android package
- Test/update: `tests/import_gallery.cpp`, `tests/records.cpp`, `tests/plugin_memory.cpp`
- Retain regression coverage: `tests/sync_packages.cpp`, `qt-app/tests/sync_engine.cpp`

**Behavior contract:** A deliberate normal import of identical bytes creates another independent library item in the requested folder. Do not add a replacement “block duplicates” toggle, a duplicate-management feature or duplicate warnings in this phase. Existing records are not rewritten or multiplied.

1. Add failing tests: same file twice in the same folder; same bytes under different names; same bytes in different folders; parallel imports; in-memory import; reopen/readback; deleting one copy leaves the other readable. Check actual item identity and row count, not only successful return values.
2. Remove plaintext-content early-return/collapse behavior in `import_file`, `import_bytes` and the post-encryption commit race check. Retain per-copy encrypted package identity and normal cleanup/locking/transaction guarantees.
3. Keep hashes and integrity checks. Do not broadly delete all code or indexes with “duplicate” in their name: tags and folders have separate uniqueness contracts, and ciphertext integrity is not the requested restriction.
4. Audit same-name file behavior and caller-specific save-once state. Explicit repeated user imports must work without silently overwriting the old item; do not accidentally turn an automatic playback retry into unlimited copies.
5. Update skipped-duplicate counts, result messages and tests that currently advertise content deduplication. Keep public/JNI fields compatible where a stable caller contract requires it; false/no-op compatibility fields can remain until a separate API cleanup.
6. Preserve sync/package replay idempotency and operation-ID deduplication: network retries must not create repeated logical records. Distinguish a new explicit import (new identity) from replaying an existing identity. Audit hash-based lookup assumptions in sync before shipping.
7. Run core import/record/plugin-memory/security and sync tests, then desktop and Android builds because the core is shared.

**Acceptance:** Intentional imports produce independent visible items on both clients. Delete/export/sync works per item. Retry/replay safety remains intact. Existing vaults reopen without an unneeded destructive migration.

## Risks and explicit boundaries

- Auth clipping may differ with native Windows styling/DPI versus offscreen Qt. Include geometry evidence and leave final on-device visual validation explicit.
- Large settings navigation changes can break signal wiring or focus. Preserve stable control identities and test every prior action, not just new navigation.
- Duplicate behavior is shared-core work with sync implications; it is not a cosmetic checkbox deletion. It increases storage use deliberately. Do not remove retry idempotency or encryption safety.
- No recursive folder size aggregation, duplicate cleaner, unrelated player redesign, dependency upgrades, commits, GUI launches or production changes are included.
